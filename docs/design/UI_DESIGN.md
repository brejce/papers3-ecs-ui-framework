## 0. 风格判定：这套 UI 是什么

> 一台只会「被使用」的机器：冷、窄、对齐、没有装饰。气质全靠**文案语法、对齐、刷新方式**。

**核心判断（去掉任何一条，这套 UI 就不成立）**：

| # | 判断 | 含义 |
|---|---|---|
| 1 | **日志即界面** | 文案是真日志语法（`> `、`//`、`[ ]`、`if(){}`），不是装饰性的「小标题样式」 |
| 2 | **黑块稀缺** | 实心黑块屈指可数（设置页**只有**底部 COMMIT），其余一律线与字 |
| 3 | **刷新可见即语义** | 局部刷新、分区推送就是这台机器的「呼吸」——不模拟动画 |

**两套载体，一套语言**。界面代码分两处，风格规则是同一份：

| 载体 | 位置 | 现状 |
|---|---|---|
| **固件页** | `main/pages/`（`manager.h` / `launcher.h` / `ime.h`） | 启动器 = 终端风 v2；输入法 = 终端风（附录 A） |
| **`.so` 应用** | `apps/settings` `apps/terminal` `apps/reader` | 终端风 v3；各 app 在自己 `.cpp` 里实现一份风格 helper |

> ⚠️ **风格 helper 目前是各 app 自己实现的**（`draw_hero` / `draw_h` / `draw_seg` / `draw_li` / `draw_toggle` / `draw_commit` …，见 `apps/settings/main/settings.cpp:167-360`、`apps/terminal/main/terminal.cpp:283+`）。
> 它们是**约定**，不是共享头文件。改风格要**三处一起改**，否则三屏会长得不一样。

## 2. 色板与灰阶

### 2.1 只有 4 个值

| 名 | 值 | 用途 |
|---|---|---|
| **PAPER** 点阵底 | 写 `0xE8E8E8`，**在 FAST 档下** = 4×4 一格黑点 | 所有白底屏的底 |
| **INK** | `0x000000` | 主文字、线框、实心黑块 |
| **GRAY** | **墨档 25**（`uint8_t`，不是 RGB） | 键名、小标题、旧日志、副提示、未选项 |
| **WHITE** | `0xFFFFFF` | 反相屏文字、黑底上的字与描边 |

辅助线色：`GLINE = 0x888888`（未选中的 1px 灰框 / 1px 细线）。禁用与说明再浅一档：墨档 `90`。

> 灰在设备上是**墨的深浅**，不是「灰颜色」。`GRAY` 在代码里是 `uint8_t 25` 传给 `so_font_draw` 的 ink 参数。
> 早先还试过 `110 → 60 → 25` 三档加深——用户说首页整体偏淡，最后定在 **25**。

### 2.2 点阵底：一个值，两种档位下的两种结果

- **FAST 档**写 `0xE8E8E8` → Bayer 量化成**每 4×4 一格黑点**的点阵，这是全项目的标准底色。
- 同样这个值在 **TEXT 档**下就是一片平滑浅灰。**底纹不一致是视觉事故**（见 §9 第 3 条「擦写同档」）。
- 文字实体的 bg 必须**同为 `0xE8E8E8`**，否则会在点阵底上抠出一块白矩形。

### 2.3 写灰的唯一正确姿势

面板对 8 位值做 4×4 有序抖动量化：`(v8 + Bayer[xy] − 8) >> 4`。要让输出**恒定**落在第 `L` 级、不起麻点，唯一取值是：

```
v8 = 16 * L + 8        (L = 0..15)
```

`0`、`8`、`255` 也天然是固定点，**其它任何值都会抖成相邻两级**。出图脚本（`tools/make_screensaver.py`）与所有画灰代码都按这条写。

**含灰的部件必须走 16 级波形**（`EPDMode{2}` TEXT/GL16 或 `{1}` QUALITY）。FAST/DU 是 2 级波形，会把灰**直接量化成白 = 灰字/灰块消失**。

### 2.4 字形绝不写回无墨像素

TTF 字形只画有墨的像素；无墨处（`0` 的孔、`├──` 的空隙、字间）**绝不写回**——背景完全由「字体下方的组件」提供。

- 合成用的底色从帧缓冲**读回**（`_read_pixel` 返回 `17*L`，要还原成 `16*L+8` 再混）。
- 合成公式：`out = bg + (ink − bg) * cov / 255`。
- 组件侧用 `TextNoBg`（`ecs/components.h`）声明「字形不铺底」——挂了这个的文本实体跳过 `fillRect`。
- 凡是要在点阵底上写字的实体，**都要挂 `TextNoBg`**，bg 设成 `0xE8E8E8`。

理由：早期写法把无墨处恒定写成白，黑字白底看不出来，**反白行就变成「黑字 + 一个白盒子」**。

### 2.5 固件侧令牌（`main/ui/theme.h`）——历史层，别在新代码里扩散

| 令牌 | 值 | 说明 |
|---|---|---|
| `BG_WHITE` | `0xFFFFFF` | 画布 / 元素底色 |
| `BG_BLACK` / `FG_BLACK` | `0x000000` | 反白底 / 正文墨 |
| `FG_WHITE` | `0xFFFFFF` | 反白面上的文字 |
| `BORDER_GRAY` | `0x888888` | 次要描边 |
| `ACCENT` | `0x333333` | 按下时的描边强调色（`systems/render.h` 按下分支用） |
| `G55` / `G99` / `GDD` | `0x555555` / `0x999999` / `0xDDDDDD` | 三档灰：主强调 / 次要文字 / 弱分隔浅底 |

**这是 Neo-Brutalist（Memphis）时代的令牌**，服务于固件自带的 widgets 页（`main/ui/widgets.h`）。新写的界面——启动器和全部 `.so` app——用 §2.1 那 4 个值，**不要**再引入 `G55/G99/GDD`。

`ui/theme.h` 里的墨色规则仍然有效：全局「墨色」设置**只压黑字**（`render.h` 里 `fg == 0x000000 ? cfg::g_cfg.ink : fg`），白字、反白、语义灰**一律不动**。

## 3. 设计原则（六条）

1. **黑块纪律**：实心黑块只给「唯一主操作」。设置页只有底部 `COMMIT`；启动器只有左侧 3px 竖墨条；终端待机屏只有负载条已填格 + EXECUTE 按钮；执行屏是整屏反相，不在此列。
2. **少盒子、多对齐**：信息行用**点线引导**（`KEY ........ VALUE`），不带外框；日志只留顶线；**盒子只留给警告**（2px 框）。
3. **全部直角，线宽 1px / 2px**：零圆角、零渐变、零装饰性抗锯齿。
4. **文案即协议**：所有可见字符串必须能当日志或代码读；正文全英文，**中文只作 `//` 副提示**。
5. **可用性优先于紧凑**：可点目标高 ≥ 52px、行间距 ≥ 8px、热区 ≥ 100×44（手指级）。
6. **不画动画**：任何「效果」必须是一次**真实的局部推送**（见 §9）。

## 4. 状态语义：强调只有三个手段

**不要用颜色或浅填充传递状态**——浅色在 2 级波形下会截成白，和未选中撞掉。实测：五档强调色里只有粉 `#ff006e`（亮度 89）够深；青 `#00d9ff`(156) 与橙 `#ff9500`(164) 只差 8 级，双双变白。

设备上的「强调」只有：

1. **反白**（黑底白字）—— 最强：选中态、开关 ON、危险待命、顶栏；
2. **描边加粗**（1px → 2px）；
3. **阴影偏移**（固件 widgets 用；终端风**不用阴影**）。

灰只用于**次要信息和弱分隔**，不承担「这是选中项」这类语义。

各部件具体形态（终端风）：

| 部件 | 选中 / 当前态 | 未选 / 另一态 |
|---|---|---|
| **段式按钮** | 2px 黑框 + INK 字 + **方括号**（`[ 3PX ]`） | 1px 灰框 + GRAY 字 |
| **开关** | 当前态 2px 框 + INK 字 | 另一态 GRAY 小字、**无框** |
| **列表项** | 2px 黑框 + 行首 `> ` | 1px 黑框；**空槽** = 灰虚线框 + `(empty)`，**不可点** |
| **导航行** | 点线行 + 右端 `>` | 同上 |

> **不整块反白**（设置六屏的定稿口径）。方括号只属于**当前生效值**。
> 固件 widgets 时代的「选中行整行反白」只剩启动器/输入法一路沿用——**两个载体的选中语言是分开定的，别互相套**。

## 5. 字号与字体

### 5.1 终端风档位（`.so` app；**禁止新增档位**）

| 角色 | px | 字间距 | 色 |
|---|---|---|---|
| 状态栏 | 20 | 2 | GRAY |
| `//` 小标题 | 18 | 2 | GRAY |
| 键名 / 状态词 / 副提示 | 19 | 1 | GRAY |
| 值 / 日志行 / 警告 | 20 | 1 | INK / GRAY |
| hero 标题（`CONFIG / SOUND`） | 38 | 0 | INK |
| 大数字（如负载 34，`%` 20） | 34 | 0 | INK |
| `> AWAITING COMMAND` / 按钮 / 日志 | 24 | 0 / 12 / 1 | INK / 白 |
| `TAP TO EXIT` | 26 | 2 | GRAY |
| `END OF LINE` | 44 | 6 | INK |

### 5.2 设置页：10 类可调字号

设置页把上表**拆成 10 个可调类别**（存 `/sdcard/apps/settings_sz.cfg`），默认值 = 上表的写死值：

| 类别 | 默认 | 调哪 | 范围 |
|---|---|---|---|
| 状态栏 | 20 | 顶栏时钟 | 14–32 |
| 大字标题 | 38 | `CONFIG` | 22–56 |
| 副标题 | 20 | `//说明` | 14–32 |
| 小标题 | 20 | `//WIFI` | 14–32 |
| 键名 | 22 | STATE 键 | 14–40 |
| 正文 | 22 | 菜单列表 | 14–40 |
| 开关 | 21 | `OFF/ON` | 14–40 |
| 按钮 | 24 | `COMMIT` | 16–44 |
| 日志 | 22 | `>提示` | 14–40 |
| 注释 | 19 | 说明小字 | 12–36 |

入口：`CONFIG / FONT` 页下半部分（原独立的「字号」页已合并进字体页）。

### 5.3 键盘字号自带

键宽/行高是围着它排的版，**不跟全局字号走**：`KB_FONT_PX = 34`（`main/ui/widgets.h`）。
渲染按实体切字号、跑完**还原成原来的值**（不是硬编码默认值 —— 见 `DEVELOPER.md` 硬约束 13）。

### 5.4 字体来源

等宽内置字体，全大写英文（代码块如 `make_you_happy` 保持原样大小写）。

1. **flash `fonts` 分区**（偏移 `0x310000`）= 兜底默认（鸿蒙 Sans SC 裁切子集）；
2. **SD `/sdcard/fonts/*.ttf`** = 可选，运行时读进 PSRAM；读取失败 → 回退内置并**清掉 NVS 记录**（不清的话每次开机白磨一次）。

**字体里没有的符号一律自绘**（`ui/icons.h` / `CustomDraw`）：箭头、退格、开关钮。别去凑字符——`⌫ ⇧ ← →` 在 GB2312 子集里没有。

## 6. 通用部件

### 6.1 终端风部件（`.so` app 与启动器）

| 部件 | 形态 | 实现 |
|---|---|---|
| 状态栏 | 高 60，底 1px 线；左 `SYS.WORLD` / `< EXIT` / `< BACK`，中 时钟（真墨迹居中），右 `BAT 100%` | `bar_static()` |
| hero 标题 | 38px 纯文字，无框无底（`CONFIG / SOUND`） | `draw_hero()` |

| 点线信息行 | 键 GRAY 19 / 值 INK 20 **右对齐**；点线用 1px×2px 短点盒，点距 6 | `draw_kv()` / `dot_leader()` |
| 段式按钮 | 见 §4 表；一组统一宽度、间隙 6 | `draw_seg()` |
| 开关 | `[OFF|ON]` 两段式，热区 ≥100×44 | `draw_toggle()` / `draw_togglerow()` |
| 列表项 | 见 §4 表；行高 ≥52，行间 ≥8 | `draw_li()` |
| 警告框 | 2px 黑框 + 文字居中（`[ FACTORY RESET ]`）；全屏唯一加粗框 | `draw_warn()` |
| 日志区 | `// LOG` 小标题 + 顶线，无外框；行 `> xxx`，新行 INK / 旧行 GRAY | `draw_log()` |
| 主按钮 | 492×80，实心黑块 + 2px 白描边 + 白字 24px（字间距 12）；左右边距 24、下边距 40 | `draw_commit()` |

**每个部件一个实体一个事务**：`startWrite → 画 → endWrite → display(足迹)`（固件侧）。
`.so` 侧用 `push(rect, why)` —— **每次推送都要带原因**，串口与 SD 同时落。

### 6.2 固件 widgets 部件（`main/ui/widgets.h`，Neo-Brutalist 层）

| 部件 | 工厂 | 几何要点 | 档位 |
|---|---|---|---|
| 纯色块 | `rect` | 直角，`border_w=0` | FAST |
| 文本 | `label` / `setting_text` | 尺寸由 TTF 实测，`Rect` 可为 0×0 | TEXT |
| 位图 | `bitmap` | 1bpp 透明 / 4bpp 灰 | 看内容 |
| 按钮 | `button` | 直角 + 黑描边 3px + 硬阴影 5px | TEXT |
| 开关 | `toggle` | 直角轨道 + 方块钮；`CustomDraw` 只画钮 | TEXT |
| 输入框 | `input_frame` + `input_text` + `cursor` | 框 2px + 3px 阴影；光标独立实体 | TEXT / FASTEST |
| 设置行 | `setting_row` + `setting_text` | 行高约 76，选中整行反白 | TEXT |
| 键盘键 | `key` | 1px 描边、**无阴影**（键距只有 6px，阴影会压到隔壁） | TEXT |
| 候选格 | `cand_cell` | 50×56，灰字 | TEXT |
| 布局 | `flex` + `add_child` | 四件套；**每页 16KB，占 ECS 存储 35%**（见 `../architecture/ECS_OPTIMIZATION.md`） | — |

### 6.3 按下反馈（固件 widgets 口径）

按下时**只改描边和阴影**：阴影收缩到 0、描边加粗 2px。**元素和文字原地不动**（用户原话：「字符也跟着变感觉不太行」）。

接线在 `systems/render.h`：
`bw = (border_w > 0 ? cfg::g_cfg.bw : 0) + (pressed ? 2 : 0)` —— **本来无框的不许凭空长框**。

> 终端风的按下反馈**只有描边 1px→2px**（无阴影），且**只推被按的那一个部件**。

### 6.4 图标自绘

`ui/icons.h`。字体里没有的符号一律代码画：箭头、退格、开关钮、应用图标。

**应用图标**（启动器里 32×32）来自 `.so` 自带的元信息，规则见 [附录 B](#附录-b应用图标与元信息m5meta)。

## 7. 每页版面

### 7.1 固件：启动器（`main/pages/launcher.h`，终端风 v2）

```
  y=12      状态栏：时钟（真墨迹居中）
  y=54      APPS                                   46px
  y=138     // 副标（应用数 / 提示）                 20px GRAY
  y=190     首行，行高 72，一屏 8 行
            ┌ 3px 竖墨条（选中行）        LX=20
            │ 序号列                      LNO_X=34 → 竖线 LDIV_X=78
            │ 图标 32×32                  LICON_X=86
            │ 应用名（24px）              LNAME_X=128
            │ 描述（16px GRAY）
            │ ··············· 点线
            └ >                            LARROW_X=488
```

- 底 `LBG = 0xE8E8E8`（整屏点阵底，**同时盖住上一页**）；细线 `LRULE = 0x888888`。
- **可点行只是触摸靶子**：不挂 `Style` / `Text`，否则按下整行重画 → 闪烁（用户原话：「app 点击后一整行都变黑闪烁，没必要啊」）。
- 文字实体一律挂 `TextNoBg` + bg `0xE8E8E8`。
- 序号/副标/状态/`more` 用**命名空间级静态缓冲**（`g_app_no[16][4]` / `g_sub` / `g_status` / `g_more`）—— `Text` 只存指针，栈上 `char buf[]` 会在渲染前失效（用户原话：「数字没有，没显示出来」）。

### 7.2 `.so` 设置：六屏主菜单 + 子页（`apps/settings/main/settings.cpp`）

共通框架：状态栏（`< BACK` / 主页 `< EXIT` + 时钟 + BAT）→ hero 标题 → `// 副提示` → 分节内容 → 底部 `COMMIT` 黑块按钮（**y=840，全页唯一实心黑块**）。

## 8. 键盘与输入法（现状规格）

版面（540×960，以 `main/pages/ime.h` 常量为准）：

```
 y=12/24    状态栏：BACK + 模式短码
 y=72       输入框（h=612，文字贴底部、y 由 line_height() 现算）
 y=620      ← 覆盖层顶边 IM_BAND_Y
 y=636      编辑条（h=48）——「正在打什么」也画在这里
 y=690      候选栏（h=56）：8 格 × 50 + 左右箭头
 y=752      键盘（4 行 × 46 + 行距 8 = 208）：10/9/9/7 = 35 键
 y=960      行 4 = en/cn · 面板键 · ← · → · space · 标点 · OK
```

铁律（每条都踩过）：

- **候选栏高度 ≈ 1.7× 字高**（34px 字配 56px 格）；原来 72px 是 2.2 倍，太胖。
- **键盘字号自带**（`KB_FONT_PX = 34`），不跟全局「字号」走；键宽按最大字号实测（`adv × size / (ascent − descent)`），别拍脑袋。
- **键面用短 ASCII**（`A/a`、`en/cn`、`?123`/`#+=`/`ABC`、`space`、`OK`），任何子集字体都有。
- **面板 3 档循环**（字母 / 数字 + 中文标点 / 英文符号）。
- **候选栏刷新时机**（用户拍板）：点候选上屏后**不刷**、候选栏留着且**还能点**；只有**又拼出新音节**才刷；英文模式全程不刷；光标 ←→ 只刷光标那一小块。
- **弹窗模式必须自带「编辑条」**：文字 + 光标同时记进覆盖层实体表。宿主输入框**只在按完成时更新**。
- **键盘 = 覆盖层（弹窗），不是切页**：盖住下方内容，收起时 `hide_overlay` 重画被盖实体。
- **键盘实体模型**：只有 **1 个容器实体**（`Rect + Style + CustomDraw + EPDMode{2}`），35 个键面不各占实体；`slot[35]` + `geo[35]` 由 `Keyboard` 结构体自持。
- **触摸自持**：容器**不挂 `Touchable`**（挂了每点一键会在 520×208 容器上脏标两次、整块键盘重推两遍），改由主循环每帧 `ui::kb::tick_g()` 自轮询 `M5.Touch` 算命中；按下只推那一个键的 `(w+2, h+2)` 足迹。
- **编辑条右侧 `×` 关闭按钮**（`IM_CLOSE_X = 476`，宽 64）——`.so` 独占屏时固件的 touch 系统直接 return，所以它也不能挂 `Touchable`，靠 `ime.h::tick()` 自持轮询。

完整设计（分层/键码/词频/验收）见 [附录 A](#附录-a输入法设计与实现全文)。

## 9. 刷新语言

| 事件 | 档位 | 推送范围 |
|---|---|---|
| 首屏 / 切屏 | FAST 铺底 → TEXT 画 → **QUALITY 整屏** | 整屏（**仅此时**） |
| 负载条变化 | FAST | 仅「旧宽 → 新宽」那一小截 |
| 数字（负载/内存/电量/百分比/时钟） | 擦 FAST、写 TEXT | 字形**墨迹**并集 × 行高 |
| 状态词 | 同上 | 墨迹并集 |
| 新日志行 | TEXT | 该行墨迹盒；满行才整日志区 |
| 光标 `_` | FASTEST | 12×3 / 18×3 |
| 开关 / 段式 / 列表项 | 擦 FAST、写 TEXT | 只推那一个部件（段式 → 新旧两个小框各推一次） |
| 警告框、`[ FACTORY RESET ]` | TEXT | 那一个框 |

风格约束：

1. **稳定态只有数字在跳、条在爬、光标在眨** —— 其余像素纹丝不动。
2. **每次 push 带 why**（串口 + SD）—— 既是调试语言，也是「机器在报告自己」。
3. **擦写同档**：擦除必须与底同档（FAST），否则点阵被洗成平滑灰，**两种底纹拼接 = 视觉事故**。
4. **切屏才整屏 QUALITY**，稳定态禁止整屏推送。
5. **分散的小更新不能合并**成一次大矩形推（并集会圈进邻近区域糊一片）；只有紧挨着的（数字 + 它下面的条）才值得合。
6. 满行日志的推屏必须是它自己这一次，**框就是框**。

> 机制细节（`_range_mod` 会累积、逻辑坐标 ≠ 面板坐标、档位双重作用、擦除段）在 `../display/EPD_TEST_MANUAL.md` §〇 与 §二。**本文只约定设计侧纪律，不重复机制。**

## 0. 三句话

1. **键盘是一个独立组件**（`ui/keyboard.h`）：它只管「键面 + 几何 + 面板切换」，

3. **页面把它们接到屏幕上**（`pages/ime.h`）：建实体、接 Sink、按 Change 只刷对应的几块。

## 2. 键盘组件（`ui/keyboard.h`）

### 2.1 按键语义

```cpp
enum Kind : uint8_t {
    K_CHAR,       // 输入 ch 这个字符（码位）
    K_SHIFT,      // 大小写（修饰键，键盘自己消化：只改自己的键面与输出端看到的 mods）
    K_BACKSPACE,  // 退格
    K_SPACE, K_ENTER,
    K_MODE,       // 中/英切换（本地输出端语义；HID 没有对应）
    K_SYMBOL,     // 面板切换 ?123 / ABC（键盘自己消化）
    K_PREV, K_NEXT,   // 候选上一页 / 下一页（位置在候选栏上，不占 33 键网格）
};
struct Key { const char* label; uint8_t kind; uint32_t ch; };
```

### 2.2 网格：4 行 33 键

```
ROW_KEYS = {10, 9, 9, 5}          // 10 + 9 + 9 + 5 = 33
SLOT_SHIFT = 19   行3 首键        字母页 = 大小写 / 符号页 = 左括号
SLOT_DEL   = 27   行3 末键        退格（键面自绘）
SLOT_MODE  = 28   行4 首键        en / cn
SLOT_PANEL = 29   行4 第 2 键     ?123 / ABC
```

**两个面板行结构完全一样**（都是 4 行 33 键），所以复用同一批键面槽（`slot[]` + `geo[]` 由 `Keyboard` 结构体自持，不再每键一个 ECS 实体），切换只换键面文字和 `Key`：

- 面板 0 字母：`q…p` / `a…l` / `shift, z…m, del` / `en, ?123, space, 。, OK`
- 面板 1 数字符号：`1…0` / `，。、；：？！""` / `（ ）《》【】—…, del` / `en, ABC, space, ￥, OK`

### 2.3 键面标签的两条规矩

- **只能用字体里真有的字**。半个中文字库的裁切字体没有 `⇧ ⌫ ←→ ★ □`，
  所以**大小写键和退格键是图元自绘**（`ui/icons.h`），label 留空。
- 标签一律**中英都能看懂**的短码：`en` / `cn` / `?123` / `ABC` / `space` / `OK`。
  大小写用 `A/a` **双色**表示当前态（当前档纯黑，另一档 66% 灰）。

### 2.4 输出端 Sink

```cpp
struct Sink {
    // mods 见 Mod：既是 HID 报文内容，也决定本地输出的大小写
    void (*on_key)(void* ctx, const Key& k, uint8_t mods);
    void* ctx;
};
```

键盘只报「按了什么键 + 修饰键状态」，落地方式由 Sink 决定：

| 输出端 | 状态 | 说明 |
|---|---|---|
| **本地输入法** | ✅ 本项目实现 | `pages/ime.h::on_sink_key` → 喂给 `ime::press` |
| **USB HID** | 🔲 映射已备好 | 取 `hid_for_key(k)` 发标准 boot 报文；USB 设备侧（CDC+HID 复合）不在组件范围 |

`hid_for_char()` 就是一张 US 布局表（`a-z`→0x04…、`A-Z`→同码位+左 Shift、标点/数字齐全）。
非 ASCII 一律返回 `{USAGE_NONE,0}` —— 中文标点电脑键盘本来按不出来，靠电脑自己的输入法，别硬发。

> **硬约束（做 USB 输出端前必须知道）**：ESP32-S3 的 USB-OTG 与 USB-Serial-JTAG **共用同一个 PHY，同时只能用一个**。
> 开了 USB-OTG 做键盘，`/dev/ttyACM0` 就消失，烧写要手动进下载模式（按 BOOT 再复位）。

## 3. 输入法逻辑层（`text/ime.h`）

### 3.1 模式

```cpp
enum Mode : uint8_t { MODE_EN = 0, MODE_CN = 1, MODE_SYMBOL = 2 /*保留，未用*/ };
```

**符号页不是「模式」，是键盘的第 2 个面板**（`K_SYMBOL` 切的）。所以 `MODE_SYMBOL` 留着没用到 ——
输入语义只有「英文直出」和「中文拼拼音」两种，符号页里点标点仍然是直出。

### 3.2 输入上下文

```cpp
struct Context {
    Mode mode, prev_mode;
    char text[64];  int caret;        // 已上屏文字（UTF-8）+ 光标（**字符**下标，不是字节）
    char py[24];    int py_len;       // 拼音缓冲（小写 ASCII）
    uint16_t list[32]; int list_n;    // 候选全集，按词频降序
    int page;                         // 当前页（0 起）
    uint16_t cand[8]; int cand_n;     // 当前页 = list[page*8 .. +8]
};
```

`MAX_CAND = 8`（候选栏一页 8 格）、`LIST_MAX = 32`（单次匹配最多收 32 个，翻页看剩下的）。

### 3.3 一次按键的返回值

```cpp
struct Change { bool text, cand, panel; };
```

**这是本层与 UI 层唯一的约定**。EPD 上「哪块脏了」直接决定刷几块屏幕，所以按键不返回新状态，
只返回**差量标记**：输入框变了 / 候选栏变了 / 键盘面板要换。

### 3.4 按键分流

```
K_CHAR  →  CN 且是字母：追加到拼音缓冲 → 重算候选
           否则：直接把字符插到光标处（英文 / 数字 / 中文标点）
K_SPACE →  有拼音：提交第 0 个候选；没拼音：插入空格
K_BACKSPACE / K_ENTER / K_PREV / K_NEXT …
```

`K_SHIFT` / `K_SYMBOL` 在键盘组件里就被消化了，不会传到状态机；
`K_PREV` / `K_NEXT` 是候选栏的翻页箭头发的（键盘组件不知道候选栏存在）。

## 4. 候选与拼音索引（`text/pinyin_store.h`）

### 4.1 索引格式 `PYIX v2`

```
header: magic "PYIX"(4) | version u16 = 2 | cand_max u16 = 32 | count u32 = 400
entry : py[12] | n u8 | pad u8 | cand[32] u16 | cnt[32] u8
                                └ 按优先级      └ 使用计数（饱和 255）
记录 110B，400 条 → 文件 44012B（43.0 KB）
```

C 端结构体有 `static_assert(sizeof(Entry) == 14 + CAND_MAX*3)` 兜着 —— **布局飘了直接编译不过**，
不会等到写坏文件才发现。Python 生成器和 C 结构体逐字节对齐（实测两边都是 43.0 KB）。

### 4.2 三级来源（优先级从低到高）

1. **内置默认表**（`pinyin_index.h`，编进固件）—— 永远有底，SD 没插 / 文件坏了照样能打字；
2. **SD 文件** `/sdcard/m5ui/pinyin.idx` —— **可升级**：换文件即换词库，不用重刷固件；
   首次开机没有这个文件时，固件会把内置表写一份下去（给你一个可改的起点）；
3. **运行时按词频调序** —— 见 4.3。

### 4.3 用真词频调序

- 每条候选有一个 `cnt`（使用计数，饱和 255）；
- 选中一个候选 → `cnt++` → 该音节内**按计数稳定排序**（计数相同保持生成器的字频基线顺序）；
- 所以：用过的字往上冒，没用过的字仍按常用度排，**不会因为用错一次就把生僻字顶到最前**；
- 粒度为 **(音节, 候选)** 而不是全局 —— `长` 在 `chang` 和 `zhang` 下各算各的，这才是拼音输入法该有的行为；
- 落盘时机：攒够 16 次选字，或离开输入法页时（只在 dirty 时写，别每选一个字就写 SD）；
- 想清零：删掉 SD 上那个文件，固件会重写一份全零的内置版本。

### 4.4 候选字符集的两道闸（关键）

| | 在哪 | 作用 |
|---|---|---|
| ① 离线 | `tools/make_pinyin_index.py` 从**字体 cmap** 生成 | 换字体 → 重跑脚本 → 索引自动跟着字体变 |
| ② 在线 | `candidates()` 里 `ttf::has_codepoint()` 过滤 | 索引没重跑、字体变小了，也只是候选变少 |

**两道加起来保证：绝不会画出方块。** 这是裁切字体（GB2312 全 6763 汉字 + 95 ASCII + 34 中文标点）
最容易踩的坑 —— 索引里有的字，字体里不一定有。

### 4.5 匹配与分页

- **精确匹配**：二分（表在加载时已按拼音字典序排好）；
- **前缀匹配**：定位首项后**轮流取**（`n` 的第一轮取 `ni/na/nan…` 各自的第 1 个候选，
  第二轮取各自的第 2 个）—— 这样打两个字母就能看到最有希望的组合，而不是被一个音节的候选淹掉；
- 400 音节规模，二分 + 顺序扫足够，不搞 Trie。

```
输入框   x=14  y=10   w=512 h=568   外框(2px描边+3px阴影) + 已上屏文字 + 拼音条 + 光标
         文字贴**底部**：x=30 y=533，光标 y=562
```

（18×3 的小条）。两者分开是为了让「只动光标」时只刷那一小块。

## 6. 墨水屏上的取舍（这节最要紧）

M5PaperS3 的面板（M5GFX `Panel_EPD`，8 位并行直驱；**不是 IT8951**）写缓冲恒为 4bit/16 灰，但**灰阶丢不丢由波形决定**。实测单行文字耗时：
QUALITY/GC16 = 780ms、TEXT/GL16 = 780ms、FAST/DU = 234ms、FASTEST/DU4 = 171ms。

| 元素 | 档位 | 为什么 |
|---|---|---|
| 页面底、大色块 | `EPDMode{1}` QUALITY | 一次画好，画质最好 |
| 已上屏文字、候选格、大小写键 | `{2}` TEXT/GL16 | 中文要 16 级灰才清晰；大小写键要出灰色 |
| 拼音条、状态栏、键盘键、光标、按钮 | `{4}` FASTEST/DU4 | 纯 ASCII 或纯黑白，171ms 手感最好 |

四条铁律（都是踩出来的）：

1. **纯灰字必须同时满足两件事**：① 墨色真的传下去（`draw_text` 的 `fg` 亮度 = 墨的灰阶档位，
   0=纯黑…255=看不见）；② 那个部件走 **16 级波形**。2 级波形会把灰压成黑白 —— 灰色 A/a 就是这么哑掉的。
2. **按下只改描边和阴影**：阴影收缩到 0、描边加粗 2px，**元素和文字原地不动**（用户原话："字符也跟着变感觉不太行"）。
3. **先擦后画，按「足迹」擦**：含硬阴影的元素，擦除矩形 = 元素尺寸 + 阴影偏移。
   候选栏取消候选时，空位画成**纯白** —— 这就是在擦上一页的候选，不擦必留残影。
4. **只刷变化的那几块**：`Change{text,cand,panel}` → 输框 / 候选栏 / 状态栏各自局部刷新；
   光标移动只刷 18×3。换页才整屏 QUALITY 全刷一次（旧页的像素不会自己消失）。

## 9. 扩展点与约束（给未来的自己）

- **加一个键**：`ROW_KEYS` 改动一个数 → 两个面板表的行结构都得跟着改（`KEY_TOTAL` 要一致），
  `SLOT_*` 常量是按下标算死的，行长度一变就要重算。
- **加一个面板**：`LAYOUT_*` 再加一张表（33 项）+ 一个 `K_SYMBOL` 式的切换键。
- **加一个输出端**：实现 `Sink` 的函数签名即可，`keyboard.h` 一行不用改。
- **换字体**：重跑 `tools/make_pinyin_index.py` 重新生成索引，否则候选里会出现字体没有的字
  （有在线那道闸兜着，最坏是候选变少，不会画方块）。
- **别在运行时写 flash 分区**：字体分区只放**默认字体**（刷固件时写），运行时换字体走
  SD → PSRAM。省磨损，也避免「用户挑字体」和「写分区」耦在一起（写坏分区连默认字体都没了）。

# 附录 B：应用图标与元信息（`.m5meta`）

`.so` app **自带**图标、名称、描述，固件启动器读出来显示（**不加载 `.so` 本身**）。

## B.1 格式

固件把 `.so` 文件读进来 → 解析 ELF 节表 → 找到 `.m5meta` 节 → 按 `so_meta_t` 解释。所以字段必须**定长、自包含、与地址无关**（不能有指针）。

```c
#define SO_META_MAGIC    0x4D355549u   // 'M5UI'
#define SO_META_VERSION  1
#define SO_META_ICON_MAX 512           // 32×32 4bpp = 512

typedef struct {
    uint32_t magic;      uint16_t version;
    uint16_t icon_w, icon_h;
    uint8_t  icon_bpp;   // 1 或 4
    uint8_t  rsv;
    uint32_t icon_bytes; // = SO_ICON_BYTES(w, h, bpp)
    char     name[32];   // UTF-8，NUL 结尾
    char     desc[96];   // UTF-8，NUL 结尾
    uint8_t  icon[512];
} so_meta_t;
```

## B.2 图标位图的视觉规范

| 项 | 规则 |
|---|---|
| 推荐尺寸 | **32×32**（启动器按这个排的行） |
| 位深 | `bpp=1`（常用，128 字节）；`bpp=4` 用于需要灰的图标（高半字节在前，0=黑 15=白） |
| 位序 | **MSB 在前**，行优先 |
| **透明度** | 位 = 1 画墨、位 = 0 **留白（透明）** |
| 形状语言 | 直角、1px 线宽为主，**不画装饰**；与 §3「全直角 / 零装饰」同语言 |

> ★ **位 = 0 必须透明，不是白。** 图标画在点阵底上：透明处保留底层像素，才不会在抖动底上抠出一个白方块（同 §2.4 的字形规则）。

## B.3 写一行就够了

```c
#include "so_meta.h"
SO_APP_META("系统设置", "网络 · 显示 · 字体 · 电源", 32, 32, 1,
            0x00, 0x00, ... );      // 位图字节，行优先
```

**三个必须知道的坑**：

1. 图标字节用**可变参数**传 —— 写成 `{...}` 会被预处理器按逗号拆成上百个参数；
2. C++ 里 **namespace 作用域的 `const` 默认内部链接** → `--gc-sections` 直接丢掉。宏里那句 `extern` 是必需的；
3. 固件读节用的是 **static 缓冲** —— 它在主任务栈（~8KB）上装不下（节表 + 名字表 + 结构体 > 7KB），放栈上会**开机 panic 重启**。

## B.4 缺元信息时

启动器回退到**文件名**（没有图标、没有描述），不报错、不影响启动。

# 附录 C：触摸反馈音

## C.1 什么时候响

**只认一次「0 → 1」的物理按下沿**，全项目只在一处判断（`main/app.h::App::update()`，紧跟 `M5.update()` 之后）：

```cpp
const int n = M5.Touch.getCount();
if (n > 0 && _prev_touch == 0) m5ui::sound::click();
_prev_touch = n;
```

放在这里而不是各页的命中代码里，因为**同一次按下会被多个消费者看到**（固件页命中、键盘轮询、`.so` 的 `so_touch`）。只认按下沿 → 任何页面、任何 app 都只响一声。

## C.2 声源

| 源 | 说明 |
|---|---|
| **内置短哔**（默认） | `M5.Speaker.tone(2000Hz, 30ms)`。板载**无源蜂鸣器**（GPIO21，M5Unified 走 LEDC/PWM），零依赖 |
| **SD 音效** | `/sdcard/sounds/*.wav`，开机整份读进 PSRAM，按下时 `playWav()` |

- 配置存**相对路径**（`sounds/click.wav`，规矩同字体），空 = 内置短哔。
- **读取失败/文件缺失自动回退**内置短哔，不会没声音。
- 上限 `WAV_MAX = 128KB`（反馈音不该长）。
- 蜂鸣器是 1-bit PWM 输出，WAV 会有「塑料味」—— **短而尖的方波反而更好听**（FC 的 2A03 音效本质也是方波）。

## C.3 节流与线程

- **60ms 限流**（`MIN_GAP_US`）：快速连点不会连成一串。丢的是声音，不是触摸事件。
- 全部**非阻塞**：`tone()` / `playWav()` 只把活交给 Speaker 内部任务，立即返回。
- **只在 ui 任务里调**（和触摸同一个任务），不需要锁。

## C.4 设置里的位置

`CONFIG / SOUND`（菜单 `04 sound`）：

```
// TOUCH
FEEDBACK              OFF | ON        ← 开关（打开时试听一声）

// VOLUME
[ 30 ]  [ 60 ]  [ 90 ]

// SOUND FILE
click.wav                     WAV  >  ← 选择 /sdcard/sounds/*.wav，选中即试听

[ TEST ]                              ← 试听当前反馈音
```

接口：`so_sound_test()`（设置页试听用，见 `apps/common/so_api.h`）。反馈音本身由**固件自动播**，`.so` 不需要管。
