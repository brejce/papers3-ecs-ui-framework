# TXT 章节/分卷在现框架下的研究（3 本真书实测）

> 数据来源：`books/` 下三本（`daming1973.txt` 9.9MB / `mushenji.txt` 17.7MB /
> `xuanhuanshijiejianlaji.txt` 2.4MB），全部逐行扫过。规则已落实成
> `tools/scan_chapters.py`（PC 侧参考实现兼回归对照基准）。
> 复现：`python3 tools/scan_chapters.py books/*.txt`

---

## 0. 结论（先看这段）

1. **规则收敛了**：三本书共 **3132 章 + 15 卷 + 1 特殊行**，逐条核对过误判/漏判（§2）。
   章标题形态高度一致：`第N章/回 + 标题`（N = 阿拉伯数字或汉字数字）。
2. **书名作者在头几行**，三本格式各异但都好取（§3）。
3. **当前框架装不下这三本书**：整本进 PSRAM（`so_read_book` 上限 512KB，
   PSRAM 总共 8MB），而最小的一本都有 2.4MB。**分章索引必须走流式/分块**（§4），
   这是本研究最关键的框架结论。
4. `.so` 里**没有 regex**，也不需要：章节标记的 UTF-8 字节是固定的，
   逐字节比即可（`my_strncmp`/`my_strstr` 已在 `str_util.h`，白名单原因见该文件头注释）。

## 1. 三本书的实测数据

| | daming1973 | mushenji | xuanhuan |
|---|---|---|---|
| 大小 | 9.9MB | 17.7MB | 2.4MB |
| 行数 / 字符 | 65062 / 3.56M | 141949 / 6.39M | 38772 / 0.91M |
| 编码 | UTF-8 全对 | UTF-8 全对 | **有 1 处坏字节**（`0xe9` 截断，需 `errors=replace` 容错） |
| 换行 | CRLF | CRLF | CRLF |
| 章（L2） | **942**（`第1章…` 阿拉伯） | **1834**（`第1章…`） | **356**（`第一章…` 汉字） |
| 卷（L1） | **15**（`第一卷…` + `第11集（上）`这类） | 0 | 0 |
| 特殊（L3） | 1（`前传`） | 0 | 0 |
| 章号 | **重排**（每卷从 1 开始，号码重复 198 个） | 顺序 1→1834 | 顺序 |
| 相邻章行距 | min 17 / 中位 64 / max 200 行 | min 39 / 中位 78 / max 149 | min 75 / 中位 108 / max 214 |

判定口径（`classify()`，C++ 可一比一照抄）：

```
行首去空白 → 特殊关键字（前传/序章/番外…，后必须结束或跟分隔符）
          → "第" + 数字(≤7字, 阿拉伯/汉字) + 标记字(卷部篇集/章回节)
          → 全行 ≤30 字；"回合"排除（第一回合≠第一回）；
            "集"后必须结束/括号/上下（防"第16集团军"）；
            同书候选<2 则整本不分章（闸门）
```

### 逐条验证过的误判/漏判（都在回归范围内）

| 样本 | 处理 | 理由 |
|---|---|---|
| `第一回合，自己秘密抢先…（53字）` | 挡掉 ✓ | 超 30 字正文；且 `回+合=回合` 专判 |
| `第195章 太平待诏归来日…` 等 6 条带 `，？（）` 的真标题 | **保留** ✓ | 曾用"带标点判正文"误杀 7 条，已删掉这条（书名章名本来就带标点） |
| `第16集团军司令…笑道：` | 挡掉 ✓ | `集` 后跟 `团`（集团一词），不是"第N集" |
| `结局全部一样。` | 挡掉 ✓ | `结局` 后紧跟正文汉字，不是独立标题 |
| `第11集（上）/第13集` | 保留 ✓ | 集后结束/括号，合法分卷形态 |

## 2. 章号重排（daming 的坑）

`第1章/第2章…` 在 daming 里出现 **10 次**（每卷重排）。所以：

- **章号不能当唯一键**：目录项用 `(卷序号, 章序号)` 或文件偏移定位，别用"第N章"字符串去重。
- 卷标题行（`第一卷 北岸惊魂`）本身就是天然分隔符：扫到 L1 就把章计数器归零。

## 3. 书名 / 作者（头几行，三本三样）

| 书 | 第 1 行 | 作者位置 |
|---|---|---|
| daming | `大明1937作者：我是猫`（书名作者粘在一起，无分隔） | 同行 `作者：` 后 |
| xuanhuan | `《我在玄幻世界捡属性》 作者：谱图`（书名号 + 空格） | 同行 `作者：` 后 |
| mushenji | 第 8 行 `牧神记` / 第 9 行 `作者：宅猪`（两行分开，前有 7 行网站声明） | 独立行 |

取法：前 10 行内找 `作者[:：]` 切出作者；书名取 `《…》` 内，否则取作者行之前
最后一个非空短行（≤20 字），再否则用文件名。mushenji 头 7 行是网站声明
（`声明：本书为…txt8080.com…` + `----用户上传之内容开始----`），解析时跳过
（`声明/----` 开头的行不入块）。

## 4. 框架结论：装不下，必须分块（最重要的一节）

| 层 | 容量 |
|---|---|
| 三本书 | 2.4 / 9.9 / **17.7MB** |
| PSRAM 总量 | 8MB（64Mbit，启动日志 `octal_psram density 0x03`） |
| `so_read_book` | 整本读，上限 **512KB**（`reader.cpp:21 MAXF`） |
| `txt::parse` | 整本解析，`max_blocks=8000` 行封顶，超了**静默截断** |

三条都不满足：**整本常驻此路不通**。分章索引本身很小
（3132 章 × `Chap{blk:u32, level:u16, title_off:u32, title_len:u16}` ≈ 14B ≈ **44KB**），
贵的是正文。所以：

1. **第一步（只做目录）**：流式扫一遍全文，只记 `(文件偏移, 级别)`，
   不存正文 → 一次 O(n) 顺序读，内存只要索引的几十 KB。
   但这需要**新的宿主导出**：`so_read_book_at(name, off, buf, len)`
   （分块读；现在的 `so_read_book` 是一次读整本，没有偏移参数）。
2. **第二步（看正文）**：点目录项 → 按偏移分块读出该章窗口 → 解析成块 → 排版。
   章平均 3–6KB（mushenji 约 3.5KB/章），窗口取 64KB 绰绰有余。
3. **不新增 Kind**：卷→H1、章→H2、节→H3（`md::Kind` 现成的，样式白拿）；
   另加 `MODE_TOC` 目录页 + 章前强制换页。
4. **mushenji 无卷**（1834 章一字排开）：目录页要支持卷分组为空的情况，
   直接按章号分段列（每 100 章一段）即可。

## 5. micropython 版 `re` 方案的对应关系（给迁移用）

以前 `re` 一句话的，现在逐字节做：

| re 写法 | C++ 侧做法 |
|---|---|
| `^第[0-9]{1,5}[章回]` | `my_strncmp=="第"` + 手工数 ASCII 数字 |
| `^第[一二三…]{1,7}[章回]` | 数字字符用一张"汉字数字字节表"逐字节比（2–3 字节/字，不解码也认得出） |
| `re.match(r"第.*?[章节]")` | **不许这么写**：`.*?` 会把正文里的"第三章……"也吞进来。本方案要求行首 + 整行独立 + 长度门槛 |
| `re.findall` 全文 | 流式逐行，O(1) 内存（只留索引） |
