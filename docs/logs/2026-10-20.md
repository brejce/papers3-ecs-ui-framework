## 四、终端 app：从 panic 到能跑（**已解决**）

### 4.1 根因：ELF 加载器把 `.rodata` 圈进了"代码地址范围"（2 字节误差）

`components/elf_loader/src/esp_elf.c` 里 `.text` 的 `size` 被 `ELF_ALIGN(size,4)` 向上取整，
而 `esp_elf_map_sym()` 又拿这个 size 当"地址区间"判断：

- `terminal.so`：`.text` 真实 **0xc6e** → 对齐成 **0xc70**；`.rodata` 起始 vaddr = 0x8f4+0xc6e = **0x1562**
- 0x1562 落进 `[0x8f4, 0x1564)` → 字符串被判定成"属于 text 段" → 映射到 ptext+0xc6e
- 再经 `elf_remap_text()` 加 `OFFSET_TEXT_VALUE = SOC_IROM_LOW - SOC_DROM_LOW = 0x0600_0000`
  → 变成**指令总线别名**；固件用 `l8ui` 读它 = `LoadStoreError` → panic → 重启

`reader.so` 不崩纯属运气：它的 `.text` 长度刚好 4 字节对齐，`.rodata` 正好落在区间外。

**修**（已 vendor 的本地补丁，升级组件时别丢）：
- `sec[ELF_SEC_TEXT].size` 存**真实大小**（供范围判断）；
- 4 字节对齐只用在 `malloc`/`memcpy` 那一侧（局部变量 `text_alloc`），并把补齐的 1~3 字节清零；
- 加载时加一行日志打出 `text/rodata/data/bss` 的运行地址与 vaddr，下次一眼能看出来。

### 4.2 第二条硬约定：输入法开着时 `.so` 不许碰触摸

`so_ime_open()` 打开覆盖层后，键盘自己在读 GT911。app 的 `page_tick` 若还调 `so_touch()`
就是**两个读者抢同一条补报序列** → 一点就崩（症状：点屏幕闪退、键盘还没建起来就重启）。
设置 app 一直是 `if (g_ime_field >= 0) return;`，终端补上同样的一行。

### 4.3 终端 UI（按用户口径重做）

- **流式排版**：`> ` 提示符跟着输出往下走（不是钉在底部）；底部固定输入行/快捷键/分隔线全删，64..940 全是文本区。
- **滚动**：上下拖 → 手势期间用 **FAST** 只推文本区（快、有残影）；停手 500ms 自动用 **QUALITY(gc13)** 重绘一次收干净。
- **键盘避让**：键盘覆盖 620..960（`main/pages/ime.h` 的 `IM_BAND_Y=620`），弹出时文本区只画到 **618**，关闭后恢复到底部。

## 五、这次踩出来的五条硬教训

1. **内部 RAM 里不许放大静态数组**。这颗芯片内部 RAM 只剩 10~20KB，几个 4KB 的 `.bss` 就能让 EPD 装表失败（→ 开机 panic 循环）、让 httpd 变哑。凡"只存字节"的缓冲一律 `heap_caps_malloc(..., MALLOC_CAP_SPIRAM)`。
2. **USB-CDC 没有硬件流控**：设备写 SD 时会把串口接收缓冲撑爆丢字节（实测 12.7KB 只到 8KB）→ 传文件必须分块 ack。
3. **`.so` 里的常量也会被当成代码地址**：加载器按"地址区间"判断符号属于哪个节，`.text` 的大小一旦被对齐取整，
   紧贴其后的 `.rodata` 就会被误判成代码、再被加上 `0x0600_0000` 变成指令别名（读它就 panic）。
4. **输入法开着时 `.so` 必须停止读触摸**（两个读者抢 GT911 = 必崩）。
5. **上传/下载要在设备刚启动时做，并且一定回读校验**。设备跑久 + 内部 RAM 紧时，`/api/ul` 会返回 200 却只落几 KB，`/api/rm`/`/api/mv` 的参数走 **POST body**（不是 query）；FATFS 的 `rename` **不覆盖**已有文件（返回 303 但没换）→ 必须"先删再改名"。脚本见 `apps/deploy_so.sh`。
