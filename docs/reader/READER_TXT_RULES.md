# 阅读器 TXT 规则（切块 · 分卷分章 · 目录）

> 这份是**照做就能实现**的规则，不是研究笔记。研究数据见
> `../research/TXT_CHAPTER_RESEARCH.md`，PC 侧参考实现 `tools/scan_chapters.py`（回归基准）。
> 目标：把任意 `books/*.txt` 切成可排版的块，并**定位每个卷/章的位置**，以显示章节目录。

---

## 0. 适用范围与两档取字节方式

规则本身与"怎么拿到字节"无关，但三本真书是 2.4 / 9.9 / 17.7MB，而
`so_read_book` 只能整本读到 **512KB**（PSRAM 共 8MB），所以分两档：

| 档 | 条件 | 取字节方式 |
|---|---|---|
| **A 整本档** | 文件 ≤ 512KB | `so_read_book` 整本进 PSRAM → 解析成块 |
| **B 流式档** | 文件 > 512KB（本项目的三本书都在这里） | ① 扫一遍只建**目录索引**（几十 KB）② 看某章时按偏移读 64KB 窗口再解析 |

> **落地现状（2026-10-20）**：两档合成了一套**滑动窗口**实现（`apps/reader/main/layout.h`）——
> 一次读 256KB 进 PSRAM 解析成块表，**页起点用文件字节偏移 + 块内行号记身份**（`PageStart{off, li}`），
> 窗口在前后滑动、页表只增不减（PSRAM 按需翻倍）。于是：大书能一直读到底、目录能跳任意章、
> 进度/续读按偏移存，都不受 512KB 限制。块表有容量上界（6000 项）时**必须**用
> `doc_cov_end()` 当覆盖范围，否则「窗口里有字节、块表里没块」会画出半页（丢字）。

**两档共用下面全部规则**，差别只在第 3 节的"位置"用来 seek 还是用来切片。

## 1. 行 → 块：分类决策表

按顺序判，命中即定；不命中就是正文段落。

| # | 输入形态 | 判定条件 | 结果 |
|---|---|---|---|
| 1 | 空行 / 只有空白（含全角空格 `　`） | — | **不入块**（分段用） |
| 2 | 头部声明 / 广告 | 前 **15 行**内，且含 `声明`/`----`/`作者上传`/`txt8080`/`www.`/`请记住`/`首发` 之一 | **丢弃** |
| 3 | 书名行 | 前 **10 行**内，去空白后 ≤ 20 字，无 `，。！？` | 记为 `book_title`，**丢弃** |
| 4 | 作者行 | 前 15 行内，匹配 `作者[:：]` | 记 `author`，**丢弃** |
| 5 | **卷行** | 见 §2 匹配规则，标记字 ∈ `卷部篇集` | 块 kind = **H1** |
| 6 | **特殊节** | 整行独立，且以 `前传/序章/序言/楔子/引子/尾声/终章/后记/番外/外传/完本感言/上架感言` 开头，**关键字后必须结束或跟分隔符**（空格/全角空格/`：`/`（`/数字） | 块 kind = **H1** |
| 7 | **章行** | §2，标记字 ∈ `章回` | 块 kind = **H2** |
| 8 | **节行** | §2，标记字 = `节` | 块 kind = **H3** |
| 9 | 其余非空行 | — | 块 kind = **PARA**（正文） |

**首行缩进**：正文段落原文多以 `　　`（两个全角空格）开头 → 排版时按"2 字缩进"渲染，
块文本里把这两个全角空格**去掉**（否则排版会再缩一次）。
卷/章标题行若也被缩进（实测 daming 有 `　　第2章 空中遭遇`），同样先去掉再判。

## 2. 卷/章匹配规则（**逐字节比，不用 regex**）

`.so` 里没有 regex；标记的 UTF-8 字节序列固定，直接比字节即可（汉字数字同样按字节比，不解码）。

```
s = 行内容，去掉首尾空白/全角空格
if s 为空                          → 正文（不入块）
if 特殊关键字开头（见 §1 第 6 条）   → H1
if s 不以 "第" 开头                 → 正文

p = 1（"第" = E7 AC AC，3 字节）
n = 0
while s[p] 是 ASCII 数字 0-9
      或 是汉字数字 {零〇一二三四五六七八九十百千两}：
    p += 该字的字节数；n += 1
    if n > 7 → 正文（编号太长）
if n == 0 → 正文

mk = s[p]                     # 标记字
if mk ∉ {卷,部,篇,集,章,回,节} → 正文

# 误判闸门（都是真书实测抓到的）
if 整行长度 > 30 字           → 正文     # 挡"第一回合，自己秘密抢先出击……"（53 字）
if mk == 回 且 s[p+1] == 合    → 正文     # 第一回合 ≠ 第一回
if mk == 集 且 s[p+1] ∉ {行尾,,空格,（,(,上,中,下} → 正文   # 挡"第16集团军司令…"

结果：
  mk ∈ {卷,部,篇,集} → H1
  mk ∈ {章,回}       → H2
  mk == 节           → H3
  标题 = 原样整行（不重编号、不拼接）
```

⚠️ **绝不能用标点当判据**：真书章名本来就带 `，`、`？`、`（上）` ——
实测「第1592章 向使当初身便死，一生真伪复谁知？」「第二百一十一章 我话讲完，谁赞成？谁反对？」
这类会被"带标点即正文"误杀（曾误杀 7 条）。

**闸门**：同一本书里 H1+H2 命中数 **< 2 → 整本不分章**（判定不可靠时，宁可不给目录）。

## 3. 位置与索引

### 3.1 目录项结构

```cpp
struct Chap {
    uint32_t off;        // ★ 文件字节偏移（唯一键）
    uint32_t blk;        // 块下标（整本档填；流式档填对应窗口内块号）
    uint16_t level;      // 1=卷/特殊节 2=章 3=节
    uint16_t title_len;  // 标题字节数
    uint32_t title_off;  // 标题在源缓冲区里的偏移
};
```

**为什么用字节偏移当键**：daming 的章号每卷重排（`第1章` 出现 10 次），章号不能当身份。
索引大小：3132 章 × 14B ≈ **44KB**，PSRAM 随便放（`g_ps` 那种静态数组也行）。

### 3.2 块要带上偏移

给 `md::Block` 加一个 `uint32_t off`（12B → 16B），解析时填该块在源文件里的起始偏移。
这样"目录项 → 块"是**一次比较**（`blk = 首个 off >= chap.off 的块`），不用重扫。

## 4. 目录页（TOC）规格

**进入**：阅读页**中间 1/3 点一下 → 中央弹窗 → `目录`**（底部按钮已取消）；`< BACK` 回阅读页；点条目跳章。
（2026-10-20 落地：`apps/reader/main/pages.h` 的 `show_toc()` / `tick_toc()`）

| 项 | 规格 |
|---|---|
| 顶部标题 | 状态栏（`< BACK` + 时钟 + BAT）+ hero `目录` 38px + `// 书名 · 卷15 章942 节0` |
| 条目行高 | 统一 **44px**（一屏 14 行，`T_Y0=170`）；字号按层级 **卷 28 / 章 24 / 节 22** |
| 缩进 | 卷/特殊节：0；章：**24px**；节：**48px** |
| 文本 | **原样标题**（`第一卷 北岸惊魂` / `第1章 大神骚扰我`），**不合成全局连续编号** |
| 当前章 | 行首标 **`> `**（= 最后一个 `off ≤ 当前页偏移` 的条目）；不用反白（终端风的选中语言是 `> ` + 2px 框） |
| 底部 | 左 `[ 上一页 ]` / 中 `x/y` / 右 `[ 下一页 ]`（段式，翻页只重画行区+底栏） |
| 跳转 | 点条目 → `pages_reset(chap.off, 0)` → `show_read(0)`：**页起点 = 该章标题行的文件偏移**，窗口直接开在那儿；跳完第一页就是这一章的标题（卷标题页后面紧跟"第1章"时，H2 会触发章前换页，所以那一页只有卷标题——纸书的卷首页就是这样） |
| 无卷的书 | mushenji 这种 1834 章一字排开：不缩进，直接列；每 **50 章**插一条浅灰分隔标（可选） |

## 5. 单文件版式（阅读页）

沿用现有 `style_of()`（`apps/reader/main/layout.h:118`），规则与它的对应：

| 块 kind | 来源 | px（默认字号 26 时） | indent | before | after |
|---|---|---|---|---|---|
| H1 | 卷 / 特殊节 | 40 | 0 | 20 | 12 |
| H2 | 章 | 34 | 0 | 16 | 10 |
| H3 | 节 | 30 | 0 | 12 | 8 |
| PARA | 正文 | 26 | 0 | 6 | 6 |

补充三条（2026-10-20 已落地，`layout.h` 的 `style_of()` 与 `walk_page()`）：

1. **字号可调**：上表是"字号 26"时的值；实际按 `style_of()` 的整数比例缩放（H1 154%、H2 131%、H3 115%），
   行距恒为 `字号 + 8`。阅读器设置页可改 22/26/30/34。
2. **章前强制换页**：H1/H2 块在排版时若本页已有内容，直接从新页开始
   （实测相邻章中位 64 行 ≈ 2–3 页，不断页会出现"上一章尾巴 + 新章标题"同页）。
3. **段首缩进**：txt 段落原文以 `　　`（两个全角空格）开头，**原样保留**（排版自然缩两字）；
   章标题行则被分章规则 trim 掉缩进（否则标题会歪）。

## 6. 边界与容错（每条都有实测来源）

| 情况 | 处理 |
|---|---|
| UTF-8 坏字节（xuanhuan 有 1 处 `0xe9` 截断） | 逐行解析失败 → 该行按 `replacement` 降级处理，**绝不整体报错**；计数记为 `bad_lines` 打日志 |
| CRLF | 每行尾去掉 `\r`（三本书都是 CRLF） |
| 全角空格缩进 | 判标题时 strip 掉（`　` = E3 80 80） |
| 章号重排 | 不用章号做键；目录显示原样 |
| 无卷 / 无章 的书 | 闸门（§2）→ 不分章，目录页只显示"全书 1 条"或直接禁掉目录按钮 |
| 超长段落 | 单行 378 字也见过；排版按宽度折行即可（现有 `wrap_run`） |
| 页数上限 | `g_ps[4096]`（布局里的静态数组）→ 超过 4096 页要改成动态或分块，**大书必须走流式档** |
| 网站声明 / 广告行 | §1 第 2 条，前 15 行内才判（正文中间出现"声明"不误伤） |

### 7.1 排版引擎的电脑端回归（`apps/reader/test/`）

分章数对上只证明"索引对"，**不证明翻页不丢字**。窗口滑块最容易漏行/重行，所以排版引擎有一套在电脑上跑的回归：
用桩替换宿主接口（`stub_so.cpp`：文件读真书、字体用等宽假字体、`so_font_draw` 把画出来的字收起来），
把 `layout.h` 原样编进去，然后：

```bash
cd apps/reader/test && ./run.sh 大明1973.txt 牧神记m.txt     # 三本全跑约 2 秒
```

| 用例 | 判据 |
|---|---|
| ① 全书顺序翻页 | 所有页面画出来的文字**去掉空白后**与原文件逐字相同（不漏行/不重行） |
| ② 从中间页续读 | 从第 501 页的块首页起，接着的 4000 字必须与原文同一偏移接上 |
| ③ 目录跳章 | 索引里抽查 20 章逐个"跳"，每页第一段文字必须就是那一章的标题 |

三本实测：玄幻 2.4MB / 大明1973 9.9MB（10996 页）/ 牧神记 18MB（20541 页）——**0 失败**。
这套回归抓出过 4 个真 bug（块表撞上界画半页、行尾截断的 UTF-8 字节读穿字符串、页表 4096 项溢出、
文件末行没有换行导致最后一行丢失），改窗口/分页相关代码后**必须重跑**。

## 8. micropython `re` → C++ 对照（迁移用）

| 以前 | 现在 |
|---|---|
| `re.match(r'^第[0-9]{1,5}[章回]', line)` | `my_strncmp` 比 `"第"` + 手数 ASCII 数字 |
| `re.match(r'^第[一二三四…]{1,7}[章回]')` | 汉字数字用**字节表**逐字比（每字 3 字节） |
| `re.search(r'第.*?[章节]')` | **禁止**：会把正文里的"第三章……"吞进来。必须行首 + 整行独立 + ≤30 字 |
| `re.findall` 全文扫 | 逐行流式扫，只留索引（O(1) 内存） |
| `re.match(r'作者[:：](.+)')` | 头 15 行内找 `作者` 的 3 字节序列 + 冒号 |

## 9. 规则文件化：怎么在现框架下做到「随时更新」

以前（MicroPython）另写一个 JSON 就能改分卷规则。现在同样能做到，**走的还是项目里已有的那套范式**
（`main/text/pinyin_store.h` 的拼音索引就是这个形状），只是把 JSON 换成**逐字节可解析的行式文本**。

### 9.1 分层：规则文件放 SD，解释规则的是 `.so`

| 谁 | 干什么 |
|---|---|
| **SD 文件** `/sdcard/m5ui/reader_rules.txt` | 规则本体（人可读、手机网页能上传替换） |
| **宿主（固件）** | 只做一件事：把该文件读成一段字节给 `.so`（`.so` 不能自己开文件） |
| **`.so`（阅读器）** | 解析规则 + 按规则分类每一行（**业务逻辑在 .so**，见 `../architecture/READER_API_SURFACE.md`） |
| **PC 工具** `tools/scan_chapters.py` | 同一套语义的参考实现 + 回归基准 |

### 9.2 文件格式（行式，KEY + 值）

第一行是版本行 `!reader-rules 1`（**允许前面有注释**，解析器在头 50 行内找它），
之后每行一条 `KEY<空格><值...>`；`#` 注释、空行忽略、**不认识的 KEY 忽略**（向前兼容）。

| KEY | 含义 | 例 |
|---|---|---|
| `V` / `C` / `S` | 卷级 / 章级 / 节级标记字 | `V 卷部篇集` `C 章回` `S 节` |
| `P` | 编号前缀（可多行） | `P 第` |
| `D` | 允许的数字形态：`A`=ASCII、`H`=汉字 | `D A H` |
| `H` | 汉字数字集合 | `H 零〇一二三四五六七八九十百千两` |
| `K` | 独立关键字（卷级，整行独立才认） | `K 前传 序章 楔子 番外 后记` |
| `R` | 拒绝对：标记字+后继字 → 判正文 | `R 回 合`（第一回合）`R 集 团`（第16集团军） |
| `L` | 标题最大字数 | `L 30` |
| `G` | 同书候选数下限（低于 → 整本不分章） | `G 2` |
| `T` / `X` / `A` / `B` | 头部行数 / 丢弃行关键字 / 作者关键字 / 书名包裹符 | `T 15` `X 声明 ---- txt8080` `A 作者` `B 《》` |

**实测"改一行就变"**（`books/大明1973.txt`）：

```
默认 (L 30, V 卷部篇集):   卷15 章942
L 12  改一行:              卷13 章784     ← 长标题（带逗号的对联式章名）被长度门槛挡掉
V 卷  改一行:              卷 9 章942     ← "第11集/第12集"不再算卷
```

### 9.3 读与生效

```
进入阅读器 app（page_init）
   └─ 宿主 so_read_text("/papers3/reader_rules.txt", buf, cap)
        ├─ 读到了 → .so 解析（校验版本行）→ 用它
        └─ 没读到/版本不对 → 用 .so 里编进去的**内置默认规则**，并打日志说明用了哪份
```

- **改文件 → 重新进入 app 即生效**，不用刷固件、不用重启设备。
- 手机浏览器 `http://<设备IP>/` 能直接上传/替换该文件（网页文件管理支持任意目录 + 建目录）。
- PC 侧一条命令推上去并校验：`tools/push_rules.sh [IP]`（上传 → 回读 `cmp` → 提示重进 app）。

### 9.4 需要新增的宿主导出（一条）

```c
// 读 /sdcard 下的文本文件（path 相对 /sdcard，拒 ".."）。返回字节数，<0 失败。
int so_read_text(const char* path, char* buf, int cap);
```
连同导出表 `ESP_ELFSYM_EXPORT`、`.so` 白名单、`API_VERSION_MINOR + 1` 一起改（见
`../architecture/ELF_PLUGIN_ARCHITECTURE.md` 的四步）。

### 9.5 ⚠️ 两个"静默失效"陷阱（都实际踩过）

1. **版本行检查不能只看第 0 行。** 规则文件开头通常是一堆 `#` 说明注释 ——
   只查 `lines[0]` 会判"文件头不对"→ **静默退回内置规则**，现象是"我改了规则却没生效"，
   而且**没有任何报错**（工具里实测踩到，改了半天以为规则没被应用）。
   做法：在头 50 行内跳过空行/注释/BOM 找 `!reader-rules`，并在日志里**报出退原因**。
2. **回退必须有日志**：`用 SD 规则（N 条）/ 用内置规则（原因：……）`。
   否则"规则文件没生效"和"规则生效了但规则本身不对"在屏幕上长得一模一样。

### 9.6 验收判据

```bash
python3 tools/scan_chapters.py books/*.txt          # 必须仍是 卷15/章942、章1834、章356
python3 tools/scan_chapters.py --rules /tmp/x.txt books/大明1973.txt   # 改规则 → 数变了才算通
tools/push_rules.sh                                 # 上传 + 回读一致
```
设备端实现后，同一本书必须给出**同样的卷/章数**（与 PC 参考实现逐数对齐）。
